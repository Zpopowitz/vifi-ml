## Product Context

- **What this is:** vifi.health — the marketing + research-hub site for ViFi, a contactless WiFi-CSI vital-signs sensing project.
- **Primary audience (the wedge):** academic researchers (PIs, PhD students) and clinical-trial Operations Managers buying research-use kits + dataset access for IRB-approved studies.
- **Secondary audience (long-term):** hospital Director of Patient Safety / Quality. Lives on `/roadmap`, not the front page.
- **Space/industry:** sits between academic ML/HCI (Hugging Face, arXiv vibe), maker hardware (OpenBCI, Adafruit), and serious lab/scientific institutions (Allen Institute, Modular, Anthropic).
- **Project type:** Astro 4 static site + Vercel serverless functions; marketing + research hub hybrid. Lives at `site/` in the monorepo.
- **Stage:** pre-FDA, pre-incorporation, pre-revenue. Solo founder. Honest about that.

## Aesthetic Direction

- **Direction:** **Editorial Lab.** Anthropic's warm-paper register + Hugging Face's data-as-design instinct + OpenBCI's hardware-photo honesty + Allen Institute's confident type. Reads like a research lab website that happens to sell kits.
- **Decoration level:** Intentional. Real captured data and real hardware photos do the visual work. No decorative ECG SVG flourishes, no abstract blobs, no gradient backgrounds, no stock photos. Subtle paper grain on the cream is optional (v2).
- **Mood:** "research paper you can buy hardware from." Should feel like reading a peer's preprint, not a SaaS landing page.
- **Reference sites:** anthropic.com (warm paper + serif display + dated release cards), huggingface.co (data-as-design + dense content grids), openbci.com (hardware-photo honesty), alleninstitute.org (confident type rhythm), modular.com (restrained editorial), arxiv.org (the extreme of "data is the design").

## EUREKA — escape the medical-tech category

The conventional move for a medical-hardware site is sky-blue + hospital photo + "trusted by clinicians" + FDA-badge aesthetic. That's wrong for ViFi because **the buyer isn't a hospital — it's an academic PI who reads papers all day.** ViFi belongs in the same visual neighborhood as the people we're selling to: academic-research-tech, not medical-marketing. Every design decision should serve this positioning. When in doubt, ask: "would a postdoc trust this?" before "would a hospital procurement officer trust this?"

## Typography

All fonts loaded via `@fontsource` packages in Astro — self-hosted, no FOUT, no Google Fonts CDN.

| Role | Font | Size / Weight | Why |
|---|---|---|---|
| **Display** (h1, h2) | **Fraunces** (variable serif, free) | h1: 64px / 500 wt; h2: 36px / 600 wt; `font-variation-settings: "SOFT" 30, "opsz" 96` | Anthropic-adjacent gravitas without copying. Variable axis lets us tone "softness" up/down per use. |
| **Body prose** | **Source Serif 4** (free) | 17px / 1.55 line-height / 400 wt | Serif body. Says "read this like a paper," puts ViFi in publishing register. The biggest aesthetic risk; on review it reads as research-lab paper, not old-fashioned. |
| **UI / labels / nav** | **Inter Tight** (free) | Buttons 15px / 500 wt; nav 14px / 500 wt | Honest sans for interactive elements. Distinct enough from default Inter to escape the slop pattern. |
| **Data / version / code** | **JetBrains Mono** (free) | 14px / 400 wt; `font-variant-numeric: tabular-nums` everywhere it appears | Code-as-design. Version numbers, dates, dataset filenames, numerical columns — all monospace as a credibility signal. |

### Scale (modular, 1.25 major-third ratio)

| Level | Size | Use |
|---|---|---|
| display-xl | 64px | Hero h1 |
| display-lg | 48px | Section h2 (when extra emphasis) |
| display-md | 36px | Section h2 (default) |
| display-sm | 28px | Subsection h3 |
| body-lg | 21px | Lede / intro paragraphs |
| body-md | 17px | Default body |
| body-sm | 15px | UI labels, captions |
| label | 12px | Meta labels (uppercase, tracked) |
| micro | 11px | Footnotes, masthead caption |

### Typography rules

- Headings: `text-wrap: balance` for h1, `text-wrap: pretty` for h2/h3
- Body: max-width 70ch for prose, 90ch for data tables
- Curly quotes (`"` not `"`), ellipsis (`…` not `...`)
- Numbers in tables and data always `tabular-nums`
- Never letterspaced lowercase

## Color

Restrained palette. Brand accent = teal (used for CTAs, links, hover, focus rings). Emerald is reserved for ECG / heart-rate signal meaning in figures and the logo — NOT for general UI. Three data-overlay hues for charts.

### Light mode (default)

```css
--paper:        #F4EFE4;   /* warm cream — primary surface */
--paper-2:      #ECE5D5;   /* deeper cream — cards, code blocks, metric blocks */
--paper-3:      #E0D8C4;   /* deepest cream — hover surfaces */
--ink:          #1A1A1A;   /* near-black — primary text */
--ink-2:        #3A3A3A;   /* dark gray — secondary text */
--muted:        #5A5A5A;   /* mid gray — labels, captions */
--rule:         #D8D0BF;   /* warm gray-cream — borders, dividers */
--accent:       #1D5C6E;   /* deep teal — brand accent, CTAs, links */
--accent-2:     #2A7A92;   /* lighter teal — hover state */
--signal:       #0E9F66;   /* emerald — ECG / HR signal in figures, in logo */
--signal-glow:  #34D399;   /* bright emerald — live HR pulse highlights */
--data-warm:    #C77E3F;   /* warm amber — deltas, comparison data */
--data-cool:    #3E6FB0;   /* muted blue — ground-truth overlay (Polar H10) */
```

### Dark mode

```css
--paper:        #131715;   /* warm dark — "lab at night," not cold corporate */
--paper-2:      #1C211D;
--paper-3:      #252A26;
--ink:          #E8E4D8;   /* warm off-white */
--ink-2:        #C8C2B0;
--muted:        #8A8478;
--rule:         #2D3330;
--accent:       #4DA3BA;   /* lighter teal for dark contrast */
--accent-2:     #6EBED4;
--signal:       #2EBB7D;
--signal-glow:  #34D399;
--data-warm:    #D89860;
--data-cool:    #6494D8;
```

### Color rules

- WCAG AA: body text 4.5:1, large text 3:1, UI components 3:1. All above ratios meet.
- Semantic distinction: `--accent` is BRAND (chrome, UI, navigation). `--signal` is SEMANTIC (ECG / HR data). They are not interchangeable. Using `--signal` for a "Submit" button is wrong.
- Dark mode: surfaces use elevation (paper / paper-2 / paper-3) AND warm tint, never just lightness inversion of light mode.
- Never `color: green` for success indicators — use `--signal` only for HR-trace data; success states get a separate `--data-warm`-adjacent color if needed.

## Spacing

- **Base unit:** 4px
- **Density:** comfortable (reading-friendly, not compact)
- **Scale:** `2xs(4) xs(8) sm(12) md(16) lg(24) xl(32) 2xl(48) 3xl(64) 4xl(96)`
- **Vertical rhythm:** paragraphs get 16-24px below; section breaks get 64-96px
- **Container padding:** 32px desktop, 20px mobile

## Layout

- **Approach:** Editorial-grid hybrid. Marketing pages (`/`, `/roadmap`, `/contact`) read like editorial — left-aligned, long line-length, generous vertical rhythm. App pages (`/kit` configurator, `/irb` generator, `/reproduce`) use a stricter grid.
- **Grid:** single-column under 1024px, two-column (40ch sidebar + 70ch content) above
- **Max content width:** 720px for prose, 1080px for data + figures
- **Line-length:** 70ch for prose, 90ch for data tables
- **Border radius hierarchy:** `sm: 2px` (inputs, cards), `md: 4px` (buttons), `lg: 8px` (image figures). **No `rounded-full` except avatars.** No bubbly large radius — that's the SaaS-template tell.
- **Breakpoints:** mobile (375), tablet (768), desktop (1024), wide (1280)

## Motion

- **Approach:** Minimal-functional. The site is reading material, not a demo.
- **Easing:** ease-out enter, ease-in exit, ease-in-out move
- **Duration:** 150-250ms for state changes; nothing slower except the one moment below
- **One motion moment per page:** the live HR trace in the hero (`/index` only) draws itself once on page load (~1.2s, ease-in-out, then stops). Everything else is static.
- `prefers-reduced-motion: reduce` → trace shows static
- Properties animated: only `transform` and `opacity`. Never layout properties (width, height, top, left).
- No `transition: all` — properties listed explicitly.

- **Logo redesign is OUT of scope for this design system.** Wordmark stays as-designed. Restructuring elements (ECG underline vs through, drop arcs at small size) is fine; redrawing the wordmark itself requires a real logo designer.

## Versioning + numbers pattern

A core design principle, not just a visual element. **Specific numbers (MAE, sample counts, subject counts, dates) live on deep pages with context, not on the homepage.** The homepage talks about the offer (open dataset, reproducible hardware, methodology) and the category claim ("$50 of WiFi hardware") — both durable across releases.

When specific numbers DO appear (on `/methodology`, `/data`, `/results`):

- Always set in JetBrains Mono with `tabular-nums`
- Always paired with provenance in plain English (`single subject, leave-one-session-out vs Polar H10`) — never a number alone
- Always linked back to the dataset version or capture session the number came from
- When a delta is shown vs a prior release, use `--signal` (emerald) for improvement and `--data-warm` (amber) for regression. Be honest about regressions — multi-subject MAE will be worse than single-subject, and that's an honest fact, not a failure.

Visible release notes (Anthropic-style cards):

- Dated by month (not by exact date) — `January 2026` not `2026-01-15`
- No version-number bragging in card copy; the date IS the version stamp
- Body copy describes what changed, not the new numbers — specifics live in the release notes page
